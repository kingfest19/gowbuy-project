## 🔌 API Endpoints (9 Total)

All endpoints are RESTful with proper HTTP methods and JSON responses.

### Authentication
- Requires user to be logged in (Django session)
- CSRF token required for PATCH/DELETE requests

### Available Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/conversations/<id>/status/` | PATCH | Change conversation status |
| `/api/conversations/<id>/urgency/` | PATCH | Update urgency score (1-10) |
| `/api/conversations/<id>/assign/` | PATCH | Assign to team member |
| `/api/conversations/<id>/followup/` | PATCH | Schedule follow-up reminder |
| `/api/conversations/<id>/category/` | PATCH | Set conversation category |
| `/api/conversations/<id>/sentiment/` | PATCH | Update sentiment indicator |
| `/api/conversations/<id>/tags/` | PATCH/DELETE | Add or remove tags |
| `/api/conversations/<id>/segment/` | PATCH | Set customer segment |
| `/api/conversations/<id>/resolve/` | PATCH | Mark as resolved/reopened |

### Error Handling
- Proper HTTP status codes (400, 404, 500)
- Consistent error response format
- CSRF protection
- User authorization checks

## 🎯 Quick Start for Testing

### 1. Access the Page
```
http://127.0.0.1:1000/vendor/messages/
```

### 2. Test an API with cURL
```bash
curl -X PATCH http://127.0.0.1:1000/api/conversations/1/status/ \
  -H "Content-Type: application/json" \
  -d '{"status": "resolved"}' \
  --cookie "sessionid=YOUR_SESSION_ID"
```

### 3. Test from Browser Console
```javascript
fetch('/api/conversations/1/urgency/', {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRFToken': getCookie('csrftoken')
  },
  body: JSON.stringify({ urgency_score: 8 })
})
.then(r => r.json())
.then(d => console.log(d))
```

```
http://127.0.0.1:1000/admin/core/conversation/
```

- Manage tags
